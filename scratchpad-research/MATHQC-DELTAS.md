## 3. DELTA — Automatic duct/pipe routing (A* with turn penalty) — **ADOPT (pure-JS, zero-dep)**

**Status: settled + verified. creador2 running the empirical turn-penalty-vs-length-only comparison.**

- **Correct algorithm:** A* with a Manhattan heuristic AND a **direction-augmented state (cell, incoming direction)** carrying a turn penalty — `edgeCost = stepLen + (turned ? bendPenalty : 0)`. A memoryless cell-only node *cannot count bends* (g(cell) doesn't know arrival direction); the (cell,dir) augmentation makes bends first-class and keeps Manhattan admissible (bends only add cost).
- **JPS is a trap:** Harabor & Grastien (AAAI 2011) — JPS is limited to uniform-cost grids; a turn penalty makes the grid non-uniform, so JPS pruning is unsound. Keep plain A* (Dijkstra only as heuristic-free fallback).
- **Pure-JS / determinism:** ~200–300 lines, no `three` in the core, CPU-only, Node-testable (fits WSL2-no-GPU/offline, matches the existing pure-core parts pattern). Determinism hinges on a **total-order tie-break** (f, then h, then monotone insertion id; no Map-iteration-order/`Math.random`/`Date` in the frontier) → route is a pure function of inputs = byte-identical waypoints (capture ethos).
- **Grid:** discrete wins (ducts ARE orthogonal). Use a **lazy `isFree(x,y,z)` predicate** over obstacle AABBs (not a dense array; `voxel-kit.mjs` is a color mesher, not a search grid). **Inflate obstacles by `radius + clearance + 0.5·gridStep`** (config-space) so the swept body clears. Post-process: A* cells → collinear-simplify → corner waypoints (elbows) → hand off to `pipe-run.mjs` (exact elbows) or B51 CatmullRomCurve3 / `rmf-frames.mjs` (rounded). Curve math NOT re-covered — this block's output IS B51's input.
- **pathfinding.js:** verified real + MIT but **2D-only and no turn cost** — disqualified twice; hand-rolling is smaller AND strictly more capable.
- **KIT DELTA (exact paths):**
  - NEW `library/parts/duct-router.mjs` + `.test.mjs` — `routeDuct({start,end,obstacles,bounds,gridStep,bendPenalty,radius,clearance,maxExpansions}) → {found,waypoints,bends,length,cost,expansions}`. Ports carry optional `dir` (leave AHU face / meet diffuser perpendicular). Zero-import core + optional thin `three` wrapper.
  - NEW `library/recipes/duct-routing-playbook.md` — auto-route vs hand-author, grid-resolution, bend-penalty tuning (few × gridStep; anchor "19 m/3 elbows beats 18 m/8"), obstacle inflation, determinism, hand-off.
  - UPDATE `library/INDEX.md` — one `parts/` row.
- **Doc check:** digest §2.6 (`occupancy grid → A*`, `C = wL·L + wB·bends + …`) is **ACCURATE and already carries the bend term** — the "grid A* only minimizes length" critique applies only to the compressed one-liner. Three refinements: (1) the digest states the cost but not the (cell,dir) search mechanism that makes `bends` first-class; (2) JPS would silently break it; (3) its CP-SAT/OR-Tools/SciPy/Ceres/Optuna stack = heavy native deps → SKIP (see §2).
- **EMPIRICAL VALIDATION (creador2, pure-JS PoC + three r185 only for the final curve):**
  - **Turn-penalty beats length-only cleanly:** same 30×10×30 grid, 3 obstacle AABBs. LENGTH-ONLY A* → length 50 cells, **5 bends**. TURN-PENALTY A* (bendPenalty=5) → length **50 cells (identical)**, **2 bends**. So among equal-length paths the turn penalty provably selects the minimum-bend one (length-only's 5 bends were a tie-break artifact). On a grid where min-bend is strictly longer, bendPenalty is the knob trading cells for elbows.
  - **Deterministic:** fixed 6-dir expansion + binary min-heap with FIFO tie-break `[f, insertionSeq]` + stale-entry skip → byte-identical waypoints/bends across runs. Confirms the pure-function-of-inputs property.
  - **Hand-off confirmed:** world waypoints drop straight into `createPipeRun({points,radius,material})`.
  - **CAVEAT to bake into the spec (creador2, EMPIRICALLY PROVEN by the 2nd flow-check):** `CatmullRomCurve3` ROUNDS corners, so a smooth-spline tube bows OFF the axis-aligned waypoints. Isolated measure: up to 0.33 m (~1.3 cells) on a 0.25 m grid. **In a real routed scenario (creador1 2nd flow-check): same waypoints → orthogonal tube PASS, rounded tube FAIL — the bow (0.20 m) clipped an obstacle the router reserved clear (clearance 0.10 m).** RULE, now proven: for strict orthogonal ductwork **tessellate straight segments** (0 bow); only use the rounded curve for pipe/cable AND **reserve clearance for the BOW, not just the radius — ≥ ~1.3·gridStep** (0.325 m would have covered the 0.20 m bow + surface reach 0.275 m). Distinguishes "duct" (orthogonal, tessellate) from "pipe/cable" (B51 rounded sweep + inflated clearance).
